Knowledge Graph vs. Web Snippet

AWS's blog claims Web Search does two different things depending on the query: factual questions get a distinct "knowledge graph" result shape, everything else gets ordinary web snippets. This page tests that claim directly instead of taking the marketing copy at face value — run a factual query and an open-ended one side by side and see what actually comes back.

What we've found so far: AWS's docs describe knowledge-graph hits as coming back with title/url null. Empirically, that has never happened here across 6 varied factual queries — every result observed so far is web-snippet shaped. The classifier below still checks for it. Why you should care: if you're designing an app around a knowledge-graph/web-snippet distinction, verify it against your own queries first — the docs and reality don't obviously agree.

Another gotcha, if you try it: querying something like "today's date" returns confidently wrong answers — different sources disagree by days. That's not a bug in this app; it's what this tool actually is. Web Search is an index of crawled, cached pages, not a live clock. A "today's date" page computes its answer when it's rendered, but the crawler only captured a snapshot from whenever it last indexed that page — so you get a stale answer served as if it were current. Why you should care: grounding via search works for facts a page states (prices, news, who's the CEO) and breaks down for anything requiring live computation relative to "now."

Parameter matrix: maxResults (1–25)

What: the discovered WebSearchTool schema only exposes query and maxResults — no date/domain filter, despite what you might expect from a search API. This sweeps maxResults at 1, 5, 10, 25 for one query so you can see how result count actually scales (it doesn't always hit the number you ask for). Why: knowing the full parameter surface up front saves you from designing around a filter that doesn't exist.
