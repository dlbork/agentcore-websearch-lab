Bedrock Native Web Search — Responses API

A second, unrelated way to get web-grounded answers out of Bedrock, launched August 2026: a built-in server-side web_search tool on the OpenAI-compatible Responses API, called against the bedrock-mantle endpoint. No AgentCore Gateway, no MCP, no Converse toolConfig — the model (openai.gpt-5.6-terra) decides on its own whether and how many times to search, and returns an answer with inline citations instead of a raw results list.

What's happening: your prompt goes straight to the model; it calls Web Search itself, as many times as it wants, within one turn. Why you should care: external_web_access is off by default below — with it unchecked, results come from Bedrock's own AWS-hosted web index/cache, not a live fetch, and your data never leaves the AWS boundary. This lab's IAM identity also holds bedrock-websearch:ExternalWebAccess, so checking the box lets the model fetch the live internet directly — useful for anything the cached index won't have (right-now prices, today's weather), but AWS flags it as a real data-exfiltration surface for untrusted prompts, so leave it off unless you're testing that arm specifically. Billing here isn't the AgentCore connector's flat $7/1,000 queries — it's model tokens plus Web Search's own pricing, decided by however many searches the model chooses to run.
